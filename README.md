# Laplace（ラプラス）

丸編み工場（機械50台・多機種混在）の稼働状況と原糸の必要量を、マネージャーがスマートフォンで管理するための道具です。

ビルドは要りません。そのまま置けば動きます。無料で運用できます。

## 公開URL

https://5gr2pb25dj-jpg.github.io/N/

`claude/factory-operation-app-s2gskj` ブランチへの push で自動的に再デプロイされます。

## iPhoneのホーム画面に追加する

1. 上記URLを **Safari** で開く
2. 画面下部の共有ボタン（□に↑のアイコン）をタップ
3. 「ホーム画面に追加」を選択 → 名前を確認して「追加」

ホーム画面のアイコンから起動すると、Safariのアドレスバーなしでアプリのように全画面表示されます。

## ファイル構成

ビルド工程はありません。そのまま置けば動きます。

| ファイル | 中身 |
|---|---|
| `index.html` | 画面と操作。CSSとJSを内包 |
| `core.js` | 計算の中核。画面に触らない部分だけ。`index.html` より先に読み込む |
| `selftest.html` | `core.js` の検算。端末のブラウザでそのまま開ける |
| `sw.js` | 圏外でも起動できるようにする。`VERSION` は `index.html` の `APP_VERSION` と合わせる |

`core.js` は素のスクリプトで、モジュールではありません。ビルド工程を増やさないためです。読み込み順に依存するので、`index.html` の `<script src="core.js?v=1">` は本体スクリプトより前に置いてください。

## 計算の検算

`selftest.html` を開くと、`core.js` の計算を37件検査して結果を出します。通れば緑、落ちれば赤です。端末のSafariでもそのまま開けます。

```
https://5gr2pb25dj-jpg.github.io/N/selftest.html
```

**計算を触ったら必ず開いてください。** ここが守っているのは、金額に直結する次のような性質です。

- 同じ品番を複数の号機で回しても、在庫を二重に数えないこと
- 今のオーダーと次のオーダーで同じ番手を使っても、二重に数えないこと
- 移行のときに号機ごとの値を足さず、最大値を採ること
- 全角で打った番手が半角と同じ山を指すこと
- 日平均が直近を重く見ること
- 水揚げkgが反数から導かれること（二重管理にしないこと）
- 編める反数がいちばん足りない糸で頭打ちになること
- 13月40日のような日付を弾くこと

検査を足すときは `T("何を守るか", () => ...)` を並べるだけです。`true` を返せば通過、文字列を返せばその文字列が失敗理由として出ます。

## 機能

### 稼働管理
- **サマリー**: 平均稼働率／稼働中号機・全号機／今週（7日以内）の予定件数／本日の水揚げ合計／残り生産量合計
- **機械一覧**: 号機番号の自然順ソート。状態は色分け＋ラベルで表示。表示形式は2種類を切り替えられる
  - **カード表示**: 1台につき1枚。稼働率・進捗・残り必要量まで載せた詳しい表示
  - **タイル表示**: アークナイツの基地画面を参考にした2列のタイル。1枚に「号機番号／稼働率のピップ＋数値／状態／案件／品番／納期／水揚げ反数・総反数／進捗バー」を収め、左端の色帯で状態が分かる。多くの号機を一目で見渡したいときはこちら
- **検索・フィルター**: 号機／品番／**番手（使用糸）**／機種／案件／次の品番を対象にしたキーワード検索、状態チップによる絞り込み。原糸タブの番手をタップすると、その糸を使っている号機をそのまま検索できる
- **登録・編集・削除**: カードやタイルのタップで編集シート。削除は編集シート内に配置。**見出しは画面上部に固定され、右上の ✕ でどこまで送っても閉じられる**（一括登録・データの保管も同じ）
- **書きかけの保護**: 入力を変えたまま閉じようとすると「破棄して閉じますか？」と確認が出る。✕・キャンセル・背景タップのどれでも同じ。水揚げの記録や完了・開始はその場で保存されるので、そのあとは確認が出ない
- **履歴**: 完了・未達・中断の別をバッジで表示。品番・期間・実績反数に加え、そのときの買った量と残った糸も記録する
- **一括登録**: 号機の数と機種を指定してまとめて作成（既存号機の続き番号から採番し、機種は全号機に設定）
- **案件（複数号機のまとめ）**: 関連する品番や、同じ品番のサイズ違いを別々の号機で流す場合に、同じ案件名を入れた号機どうしを1つのまとまりとして扱える。糸の集計も案件の単位で行われる。一度入力した案件名はプルダウンで選べ、空欄にすれば外れる。ホームで案件ごとの合計進捗を確認でき、タップすると一覧がその案件だけに絞り込まれる

### データの保管
- **書き出し**: ホームの「データの保管」から、全号機のデータをJSONファイルとして書き出せる。iPhoneでは共有シートが開くので「ファイル」アプリやメモ、メールなどに保存できる。共有が使えない環境ではダウンロード、それも使えない場合は画面上のテキストを長押しでコピーする
- **復元**: 書き出したファイルを選ぶか、テキストを貼り付けて読み込む。読み込むといまの内容はすべて置き換わるため、実行前に確認が出る。壊れたデータや空のデータは読み込まず、いまの内容もそのまま残る
- **書き出しの催促**: 一度も書き出していない、または最後の書き出しから14日以上経つと、ホームの「データの保管」に赤い印が出る
- **バージョン確認**: 「データの保管」の説明行に、いま動いている版（`Ver 2026.08.31-5` など）が出る

### 生産・原糸管理
- **生産オーダー**: 品番ごとに反数・重量（1反あたりのkg）・開始日・次回予定日を登録。合計生産量は「重量 × 反数」で自動計算
- **番手**: 表糸・中糸・裏糸それぞれの番手を登録。一度入力した番手は次回から入力欄のプルダウンで選べる
- **糸の在庫**: 在庫は**番手ごとに1つ**の台帳で持つ。糸は倉庫にあるものであって号機のものではないため、号機には持たせない。同じ番手を何台で使っていても、引き算の相手はこの1つの数字になる。編集シートでも原糸の画面でも同じ数字を書き換える
- **最初に買った量**: その品番のために手配した総量。これはオーダー単位の記録なので号機に残る。「買った量を在庫に足す」で、届いた糸を倉庫の在庫へ加算できる（上書きではなく加算）
- **実ロス率**: 「買った量 − 倉庫の残量 = 使った量」と、計算上の消費量（生産量 × 交編率）を比べて、実際に何%のロスが出たかを糸ごとに表示。設定のロス率を超えている糸は赤くなる。**その番手を他のオーダーでも使っている場合は表示しない**（倉庫の残量からその号機の消費を割り出せないため）
- **完了**: 「この品番を完了する」でオーダーを履歴に移し、号機を空にする。反数に届いていない場合は確認画面と履歴に「未達」として残る。交編率・番手はそのまま引き継ぎ、買った量だけ0に戻す。倉庫の在庫は号機と無関係なのでそのまま
- **交編率**: 表糸・中糸・裏糸の比率(%)を登録。合計が100%でない場合は警告を表示
- **原糸必要量の自動計算**: 下記の式で表・中・裏それぞれの必要量を算出
- **番手ごとの集計**: 糸は番手の単位で仕入れるため、品番・サイズ違い・使用位置（表/中/裏）をまたいで同じ番手をひとまとめに集計する。これが実際の手配単位で、**在庫を入力する場所もここ**。「次」の品番の必要量も最初から含めて数える
- **設定の点検**: 交編率の合計が100%でない号機と、交編率はあるのに番手が未設定の号機を、原糸の画面の先頭に挙げる。どちらも必要量や過不足が当てにならなくなるため、発注を決める画面で目に入るようにしてある
- **案件・品番ごとの集計**: 案件名を付けていればその単位、無ければ品番の単位で集計。**同じ品番のサイズ違い（口径違いの号機）は同じ案件名を付けるとひとまとまり**になり、サイズ別ではなくまとめて糸量を管理できる
- **編める反数の自動計算**: 「倉庫の在庫 ÷ 1反あたりの消費量」で**今ある糸であと何反編めるか**を算出し、残り反数と比較して不足反数を表示。ロスで理論どおりに減らないため、在庫を直すたびに再計算される
- **次の品番**: 進行中のオーダーとは別に、次の品番の反数・重量・開始日・完了予定日・番手・交編率・糸量を登録できる。糸を先に手配するための必要量も算出
- **生産の開始**: 「この品番を開始する」で次のオーダーを現在のオーダーへ引き上げる。開始日は今日、状態は「稼働中」になり、開始時にアニメーションが流れる
- **途中切り替え**: 残反がある状態でも切り替えられる。その場合は確認画面と案内文に残反数が出て、履歴に「中断」として実績（何反/何反）が残る
- **履歴**: 切り替えで終了・中断したオーダーを編集画面で確認できる（品番・期間・実績反数・中断の有無）。7件以上ある場合は「すべて表示」で全件に切り替えられる
- **完了予測**: 水揚げを記録した日から日平均の反数を求め、残りを消化しきる日を予測。予定日と比べた遅れ・前倒しも表示。平均は**直近ほど重く**見る（半減期7稼働日・直近30稼働日まで）ので、立ち上がりの遅さをいつまでも引きずらない
- **水揚げ記録**: 毎朝の水揚げを反数で記録すると累計・残り生産量が更新され、原糸必要量が自動で再計算される。シークバーは1反刻みで動き、kg換算値も併記。記録の取り消しにも対応
- **本日の水揚げ（まとめて記録）**: 号機ごとにシートを開かずに、一覧のまま反数を入れて一度に記録する。ホームの「本日の水揚げ」か、号機一覧の下部ボタンから開く。欄はその日の**合計反数**で、すでに記録があれば置き換わるので、同じ日に二度開いても二重には足されない。50号機を1巡するのに**52操作**（従来は号機ごとに4操作で200操作）

## 計算式

```
合計生産量 = 重量(1反あたりのkg) × 反数
原糸必要量 = 生産量(kg) × 交編率(%) × (1 + ロス率(%))
日平均の反数 = Σ(その日の反数 × 重み) ÷ Σ(重み)   重み = 0.5^(何稼働日前 ÷ 7)
完了予測日   = 今日 + ceil(残り反数 ÷ 日平均の反数)
1反あたりの糸 = 重量 × 交編率(%) × (1 + ロス率(%))
編める反数    = floor( min( 倉庫の在庫 ÷ 1反あたりの糸 ) )
使った量      = 最初に買った量 − 倉庫の残量
実ロス率      = 使った量 ÷ (水揚げ済みの生産量 × 交編率) − 1
```

数量は kg・% とも**小数第2位**まで入力・表示できます。反数は整数です。

完了予測の母数は「水揚げを記録した日」です。動かさなかった日は含めないため、稼働日ベースのペースになります。単純平均ではなく**直近ほど重み**を付けます。半減期は7稼働日で、7稼働日前の実績は今日の半分の重みになります。さかのぼるのは直近30稼働日までです。単純平均だと、立ち上がりが遅かった分をいつまでも引きずって予測が遅くなるためです。

- **全体必要量**: 合計生産量を基準にした、オーダー全体で必要な糸量
- **残り必要量**: 編残（合計生産量 − 水揚げ累計）を基準にした、これから必要な糸量
- **過不足**: 倉庫の在庫 − 残り必要量（マイナスは不足）。在庫は番手ごとに1つなので、同じ糸を使う号機どうしで二重に数えることがない
- **編める反数**: 今ある糸で編める反数。残り反数を下回っていればその差が不足反数
- **実ロス率**: 買った量から実際に減った量を、計算上の正味消費量と比べた比率。設定のロス率より大きければ、不良や糸切れで想定以上に使っていることになる

ロス率の既定値は **3%**（＝×1.03）で、機械ごとに変更できます。

**計算例**（合計生産量1000kg／交編率 表50%・中20%・裏30%／ロス率3%／水揚げ累計400kg）

| 糸 | 全体必要 | 残り必要 |
|---|---|---|
| 表糸 | 515.00 kg | 309.00 kg |
| 中糸 | 206.00 kg | 123.60 kg |
| 裏糸 | 309.00 kg | 185.40 kg |

## データについて

- データは**端末のブラウザ内（localStorage）**に保存されます。アプリを閉じても消えませんが、端末・ブラウザをまたいだ共有はされません。
- 保存キー:

| キー | 中身 |
|---|---|
| `factory-machines-v1` | 号機の配列 |
| `factory-stock-v1` | 糸の在庫台帳（番手ごと） |
| `factory-stock-migrated` | 移行時に値が食い違った番手（「確認した」で消える） |
| `factory-list-mode` | 一覧の表示形式 |
| `factory-last-backup` | 最後に書き出した日時 |
| `factory-boot-seen` | 起動画面を通しで見せた日 |

- **保存が失敗したときは、直前の入力を取り消して画面と保存先をそろえます。** 空き容量が尽きた状態で入力だけ進むと、画面には出ているのに保存されていない、という食い違いが起きるためです。
- **保存先の使用量を見て、7割で知らせます。** 満杯になってから知らせても手遅れなので手前で出します。目安として50号機・1年ぶんの水揚げ履歴で約0.8MB、上限は概ね5MBです。
- **端末を替えるときや、ブラウザの保存データを消す前には必ず書き出してください。** ホームの「データの保管」から行えます。
- 書き出したファイルには在庫台帳も入ります（`version: 2`）。`version: 1` の古い書き出しを読み込んだ場合は、号機ごとの糸量から台帳を作り直します。
- 複数端末での共有や既存の Notion／GAS 基盤との連携が必要になった場合は、保存処理（`loadMachines` / `loadStock` / `saveMachines`）を差し替えることで対応できます。

## データを全部消す

保存されているのは端末の中だけなので、外からは消せません。消したいときは、
URLの末尾に `?reset=1` を付けて開いてください。

```
https://5gr2pb25dj-jpg.github.io/N/index.html?reset=1
```

何号機・記録何件・在庫何番手を消すかと、最後に書き出した日を出したうえで、
確認を2回取ってから消します。`factory-` で始まるキーだけを消すので、
他のサイトの保存データには触れません。消したあとURLから `?reset=1` は
外れるので、再読み込みで二度目が出ることはありません。

**画面にボタンは置いていません。** 誤って押すと工場のデータが消えるためです。
消す前に「データの保管」から書き出しておいてください。元には戻せません。

ホーム画面に追加したアプリから消したい場合は、そのアプリを開いてから
アドレスを打ち替えることができないので、いったんSafariで上のURLを開いて
消してください。ホーム画面のアプリとSafariで保存が分かれている場合は、
ホーム画面のアプリを削除して追加し直すのが確実です。

### 糸の在庫台帳

`factory-stock-v1` に、番手をキーにして持ちます。

```json
{ "30/1": { "label": "30/1", "kg": 1200, "updatedAt": "2026-09-02" } }
```

キーは `countKey()` でそろえた文字列です。全角の数字と `／` を半角へ直し、空白を詰め、大文字にします。そろえないと「３０／１」と「30/1」が別の糸として二重に管理されてしまいます。

**なぜ号機ではなく番手に持たせるのか。** 糸は倉庫にある1つの山であって、号機のものではありません。号機ごとに持たせると、同じ糸を複数の号機に書いたときに集計が足し合わせてしまい、実際より在庫が多く見えます。以前はこうなっていました。

| 状況 | 実在庫 | 必要量 | 旧・表示 | 正 |
|---|---|---|---|---|
| 同じ品番を2号機で回す | 3000kg | 4000kg | 足りる ＋2000kg | 1000kg不足 |
| 1号機・今と次が同じ番手 | 500kg | 1800kg | 800kg不足 | 1300kg不足 |

上の行が危ないほうです。1000kg足りないのに「余る」と出るため、発注を逃してラインが止まります。しかも号機ごとの欄しかない以上、**正しく入力する方法が存在しませんでした**。1か所にだけ書けば他の号機が過剰に不足と出て、全部に書けば倍になります。

**移行のしかた。** 号機ごとに入っていた値は、番手ごとに**最大値**を採ります。足すと二重に数えることになるためです。値が食い違っていた番手は `factory-stock-migrated` に控えて、原糸の画面の先頭に「在庫のまとめ直し」として出します。読まれずに消えると発注を誤るので、「確認した」を押すまで残ります。

## 起動画面

背景の写真の上に、アプリ名だけを出します（約1.5秒）。画面をタップすればすぐスキップできます。

```
        L A P L A C E
        ─────────────
```

出すのはこれだけです。紋章も、副題も、`Loading.` も、稼働状況の説明文も置きません。以前は稼働台数や不足番手を書き出していましたが、起動時の1.5秒で読める情報ではなく、同じことはホームの画面が常に出しています。

### 題字の動き

動きは2つだけです。

1. **字が絞り込まれる**（0.12s 待って 1.15s）。字間 0.46em・ぼかし7px の状態から、字間 0.30em・ぼかし0へ。`cubic-bezier(0.16, 0.84, 0.24, 1)` で終わりをゆるめる
2. **細い罫が中央から左右へ引かれる**（0.46s 待って 0.74s）。幅0から58%へ

**開き始めの字間 0.46em は、はみ出さない上限から決めています。** `white-space: nowrap` なので、広げすぎると端が切れます。実測すると、いちばん狭い320px幅の端末で、開いたときの字幅は270pxに対し枠が282pxです。字の大きさを変えたら必ず測り直してください。

**`text-indent` は字間の半分**（0.30em に対して 0.15em）にしてあります。字間は最後の1文字の後ろにも入るため、中央に置くとその半分だけ左へ寄って見えます。全量を戻すと今度は右へ行き過ぎます。最初これを間違えて7pxずれていました。

### 軽さについて

動くのは題字1行と罫1本だけ。背景は静止画1枚。Canvas も WebGL も使っていません。

**起動画面は毎回必ず通る場所なので、軽さを最優先してください。** 以前レイマーチングで廃都市を描く版を入れましたが実機で重く、撤去した経緯があります。

### 背景画像について

`boot-sky.jpg` は**リポジトリ所有者がアークナイツを参考に独自に生成した画像**です（62KB）。取り込む際、下端に入っていた文字列の帯を切り落としてあります（1333×784 → 1333×748）。

横長の画像を縦画面に `cover` で敷いているため、表示されるのは中央の一部です。見せたい位置を変えたい場合は `.boot` の `background-position` を指定してください（既定は中央）。

差し替える場合は `index.html` の `url("boot-sky.jpg?v=3")` の番号を上げてください。`sw.js` の先読み一覧にも同じ文字列で入っているので、そちらも合わせます。

**第三者の著作物（ゲームのスクリーンショットや公式ビジュアルなど）をここに置かないでください。** このリポジトリは公開されており、GitHub Pages から誰でも取得できます。置くのは自作の画像か、利用が許諾されている画像に限ってください。

### ホーム画面のアイコンについて

`apple-touch-icon.png`（180）・`icon-192.png`・`icon-512.png`・`favicon.png`（48）の4枚は、**リポジトリ所有者が独自に生成した低ポリゴンの結晶の画像**を元にしています。元画像は 1365×768 の横長で、中央に「PROJECT CONTROL」の文字が横断していました。アイコンは正方形なので、次の手順で作っています。

1. 文字の帯（行333〜435）だけを取り出す。この帯の中で結晶がとる明るさは最大113なので、しきい値150（＋5px膨張）で文字だけが分離できる
2. その領域を拡散（ヤコビ反復600回）で埋める。上下から線形に引き伸ばす方法だと、文字の縦棒がスジになって残る
3. 結晶の左右端（x387〜1071）の中心 x=729 を軸に、高さいっぱいの 768×768 を切り出す
4. LANCZOS で4サイズに縮小する

修復した部分は等倍（ホーム画面の60pt）ではほとんど見えませんが、512では中央右にわずかなにじみが残ります。差し替える場合は、**必ず60pxまで縮めてから**判断してください。細部の鮮明さより、輪郭が読めるかどうかで決まります。

差し替えたら `index.html` と `manifest.json` と `sw.js` の `?v=2` の番号を上げてください。iOS はアイコンを URL 単位で強く保持するため、番号を上げないとホーム画面のアイコンが変わりません。

### 表示する回数

1日に何度も開く道具なので、通しで見せるのは**その日の初回だけ**です。2回目以降は260msで抜けます。判定は `factory-boot-seen` に入れた日付でしています。

短いほうでは `.boot` に `quick` を付けて、`animation` を使わず最終形のまま出します。1.15秒の動きを260msで切ると、字間が開いたまま消えて崩れて見えるためです。動きを減らす設定（`prefers-reduced-motion`）の端末でも同じ扱いにしています。

### バージョンの確認

以前は起動画面の左下に出していましたが、名前だけにしたので外しました。いまは「データの保管」を開くと出ます。

### 調整のしかた

表示時間は起動画面用スクリプト内の `DURATION`、文字の出る速さは `q / 11` の除数、行の間隔は `i * 145` の係数です。背景の見え方は `.boot::before` の暗幕で調整します。不要になった場合は `<div class="boot" id="boot">` のブロックと起動画面用スクリプトを削除してください。`prefers-reduced-motion` を有効にしている端末では自動的に短縮されます。

## デザイン

モバイルゲーム「アークナイツ」のUIを参考にした構成。ぼかした施設内観風の背景（`bg.jpg`）の上に明るい半透明パネルが浮かぶレイアウト、彩度を抑えた配色に青（`#29a1e0`）のアクセント、小さな英字ラベル（`sku` `uptime▶` `output▶`）の併記、左に見出しブロックを置く行レイアウトを採用しています。状態は塗りタグ、糸は系統色（表=青／中=橙／裏=緑）で識別します。

号機一覧のタイル表示は同ゲームの基地画面を模しており、暗いタイルを敷き詰め、左端の色帯で状態、名前の右のピップで稼働率、右下の大きな数字で反数を示します。

背景画像はCSSの図形とぼかしから生成したオリジナル画像で、外部素材や外部CDNには依存していません（約26KB）。

`bg.jpg` を差し替えた際は、`index.html` の `url("bg.jpg?v=N")` の番号を上げてください。ブラウザが古い画像をキャッシュしたままになるのを防ぐためです。

## 更新が反映されないとき

ホーム画面に追加したアプリは、iOSが以前読み込んだ画面を持ち続けることがあります。更新したのに変わらない場合：

1. **Safari**（ホーム画面のアイコンではなく）で `https://5gr2pb25dj-jpg.github.io/N/?r=1` のように末尾に `?r=1` を付けて開く。数字を変えれば毎回新しく取得されます
2. 起動画面の右下、またはホームの「データの保管」に出る `Ver` の日付で、いま動いている版を確認できます
3. ホーム画面のアイコンから開いた場合は、画面を下に引っ張って更新（プルダウン）

**「設定 → Safari → 履歴とWebサイトデータを消去」はしないでください。** 登録した号機のデータも一緒に消えます。

`sw.js`（Service Worker）を入れてあるため、一度新しい版を読み込めば、それ以降は起動のたびにネットワークから最新の画面を取りに行きます。圏外のときは直前に取得したもので動きます。

### 更新を出すときの手順

`index.html` の `APP_VERSION` と `sw.js` の `VERSION` を**両方**同じ値に上げてください。値が変わるとキャッシュが作り直されます。

## 意匠の規則

**この意匠は図形を置いて作るものではありません。大きな平面をいくつかの黒の濃さで塗り分けて作ります。**
参照した実画面は、要素が「明るい面」と「暗い部品」の2値しかない画面がほとんどでした。枠線・影・模様・記号はほぼ使われていません。

迷ったら**足すのではなく引いてください。**

### 面の濃さ

情報の区切りは、枠線ではなく**明るさの段差**で作ります。

| 変数 | 値 | 使いどころ |
|---|---|---|
| `--v0` | `#ffffff` | 最も明るい面（ほぼ使わない） |
| `--v1` | `#ececec` | 明るい面。パネルの地 |
| `--v2` | `#dcdedf` | 明るい面の中の一段沈んだところ |
| `--v3` | `#c4c6c7` | 明るい面の区切り |
| `--v4` | `#313131` | 暗い部品。操作できるもの |
| `--v5` | `#1e1f21` | 暗い面 |
| `--v6` | `#121315` | 最も暗い面・銘板 |

号機タイルの状態も、色帯ではなく**面の明るさ**で示します。面の中は左上から右下へ落とし、光の当たった板に見せます。

| 状態 | 面（左上 → 右下） |
|---|---|
| 稼働中 | `#43484e` → `#3a3f44` |
| 段取り中 | `#32363a` → `#292d30` |
| 停止 | `#232629` → `#1c1e21` |
| 計画停止 | `#181a1c` → `#131416` |

**タイル内の振れ幅は、状態間の段差より小さく抑えてください。** これを守らないと、明るい面の暗い角と、暗い面の明るい角が同じ明度になり、状態の区別が崩れます。

現在の値で測ると、タイル内の幅は 5.7〜8.2、状態間の余裕は 4.1〜9.8 です（相対輝度）。値をいじったときは、**明るいほうの右下と、暗いほうの左上を実際に測って**、余裕が残っていることを確かめてください。

グラデーションをかけてよいのは**暗い面だけ**です。明るい面（パネル）は平らに保ちます。

### 置かないもの

- **枠線**（`border: 1px solid rgba(255,255,255,…)` は全廃しました）
- **背景の模様・地紋・グラデーション**
- **ピップ、色帯、矢印記号（▶）、装飾的なアイコン**
- **意味のない色**。指標ごとに色を変える、糸の種類を色で重ねる、といったことはしない

### 色を使ってよい場面

| 色 | 用途 |
|---|---|
| 青 `#29a1e0` | **いま選ばれている／確定する**もの。それ以外に使わない |
| 琥珀 `#d79a1b` | 画面の節の帯（`.ysec`）のみ |
| 赤 `#cf4a3f` | 不足・超過など、対処が要る数値 |
| 状態色 | 号機の状態を示す小さな塗りの点のみ |

### そのほか

| 規則 | 内容 |
|---|---|
| **角丸を入れない** | 直角のみ。完全な円は可 |
| **極小の英字ラベル** | 大文字・字間を大きく開く・コロンで終わる（`SKU:`） |
| **数字は細く大きく** | `font-weight: 300`。太らせない。単位と分母は小さく薄く。桁が並ぶところは `font-variant-numeric: tabular-nums` |
| **書体** | `body` の1か所だけで指定し、全要素が継承する。個別に `font-family` を足さない。欧文はSF Pro、和文はヒラギノに落ちるよう順に並べてある（字ごとに前から探されるため、この順で別々に決まる） |
| **影** | 面を持ち上げる最小限（`--lift`）だけ |
