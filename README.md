# 工場稼働管理アプリ

丸編み工場（機械50台・多機種混在）の稼働状況と原糸の必要量を、マネージャーがスマートフォンで管理するためのツールです。

ビルド不要の単一 HTML ファイル（`index.html`）で構成されており、無料で運用できます。

## 公開URL

https://5gr2pb25dj-jpg.github.io/N/

`claude/factory-operation-app-s2gskj` ブランチへの push で自動的に再デプロイされます。

## iPhoneのホーム画面に追加する

1. 上記URLを **Safari** で開く
2. 画面下部の共有ボタン（□に↑のアイコン）をタップ
3. 「ホーム画面に追加」を選択 → 名前を確認して「追加」

ホーム画面のアイコンから起動すると、Safariのアドレスバーなしでアプリのように全画面表示されます。

## 画面構成

下部のタブで3つの画面を切り替えます。起動時は「号機一覧」が開きます。

| 画面 | 内容 |
|---|---|
| ホーム | 本日の水揚げ、案件、要注意の号機、今週の予定、糸の不足をまとめたダッシュボード。各行をタップすると該当号機の編集画面へ（案件は一覧の絞り込み、糸の不足は原糸タブへ） |
| 号機一覧 | 号機の一覧。検索・状態フィルター・登録・編集。検索欄の右のボタンで「カード表示」と「タイル表示」を切り替えられ、選択は次回以降も保持される |
| 原糸 | 上段が**番手ごと**（品番やサイズ違いをまたいだ、実際の手配単位）、下段が**案件・品番ごと**の内訳。いずれも「残り必要量・現在庫・過不足」を表示し、過不足がマイナスの糸はその量だけ追加手配が必要。番手をタップするとその糸を使う号機を検索 |
| ガント | 各号機の工程を時間軸で表示。開始日から次回予定日までのバー、水揚げの進捗、今日の位置、遅れの見込み、次の品番の予定を表示。開いたときは今日が左端に来る。号機・品番の列は横スクロールしても固定 |

## 機能

### 稼働管理
- **サマリー**: 平均稼働率／稼働中号機・全号機／今週（7日以内）の予定件数／本日の水揚げ合計／残り生産量合計
- **機械一覧**: 号機番号の自然順ソート。状態は色分け＋ラベルで表示。表示形式は2種類を切り替えられる
  - **カード表示**: 1台につき1枚。稼働率・進捗・残り必要量まで載せた詳しい表示
  - **タイル表示**: アークナイツの基地画面を参考にした2列のタイル。1枚に「号機番号／稼働率のピップ＋数値／状態／案件／品番／納期／水揚げ反数・総反数／進捗バー」を収め、左端の色帯で状態が分かる。多くの号機を一目で見渡したいときはこちら
- **検索・フィルター**: 号機／品番／**番手（使用糸）**／機種／案件／次の品番を対象にしたキーワード検索、状態チップによる絞り込み。原糸タブの番手をタップすると、その糸を使っている号機をそのまま検索できる
- **登録・編集・削除**: カードタップで編集シート。削除は編集シート内に配置
- **履歴**: 完了・未達・中断の別をバッジで表示。品番・期間・実績反数に加え、そのときの買った量と残った糸も記録する
- **一括登録**: 号機の数と機種を指定してまとめて作成（既存号機の続き番号から採番し、機種は全号機に設定）
- **案件（複数号機のまとめ）**: 関連する品番や、同じ品番のサイズ違いを別々の号機で流す場合に、同じ案件名を入れた号機どうしを1つのまとまりとして扱える。糸の集計も案件の単位で行われる。一度入力した案件名はプルダウンで選べ、空欄にすれば外れる。ホームで案件ごとの合計進捗を確認でき、タップすると一覧がその案件だけに絞り込まれる

### データの保管
- **書き出し**: ホームの「データの保管」から、全号機のデータをJSONファイルとして書き出せる。iPhoneでは共有シートが開くので「ファイル」アプリやメモ、メールなどに保存できる。共有が使えない環境ではダウンロード、それも使えない場合は画面上のテキストを長押しでコピーする
- **復元**: 書き出したファイルを選ぶか、テキストを貼り付けて読み込む。読み込むといまの内容はすべて置き換わるため、実行前に確認が出る。壊れたデータや空のデータは読み込まず、いまの内容もそのまま残る
- **書き出しの催促**: 一度も書き出していない、または最後の書き出しから14日以上経つと、ホームの「データの保管」に赤い印が出る

### 生産・原糸管理
- **生産オーダー**: 品番ごとに反数・重量（1反あたりのkg）・開始日・次回予定日を登録。合計生産量は「重量 × 反数」で自動計算
- **番手**: 表糸・中糸・裏糸それぞれの番手を登録。一度入力した番手は次回から入力欄のプルダウンで選べる
- **糸量**: 「最初に買った量」と「現在の糸量」を別々に登録する。買った量はその品番のために手配した総量（追加購入分も足す）、現在の糸量は今この号機にある量。「現在の量にも入れる」で手配直後の値をまとめて入れられる
- **実ロス率**: 「買った量 − 現在の糸量 = 使った量」と、計算上の消費量（生産量 × 交編率）を比べて、実際に何%のロスが出たかを糸ごとに表示。設定のロス率を超えている糸は赤くなる
- **完了**: 「この品番を完了する」でオーダーを履歴に移し、号機を空にする。反数に届いていない場合は確認画面と履歴に「未達」として残る。残った糸は次でも使うため、現在の糸量・交編率・番手はそのまま引き継ぎ、買った量だけ0に戻す
- **交編率**: 表糸・中糸・裏糸の比率(%)を登録。合計が100%でない場合は警告を表示
- **原糸必要量の自動計算**: 下記の式で表・中・裏それぞれの必要量を算出
- **番手ごとの集計**: 糸は番手の単位で仕入れるため、品番・サイズ違い・使用位置（表/中/裏）をまたいで同じ番手をひとまとめに集計する。これが実際の手配単位になる
- **案件・品番ごとの集計**: 案件名を付けていればその単位、無ければ品番の単位で集計。**同じ品番のサイズ違い（口径違いの号機）は同じ案件名を付けるとひとまとまり**になり、サイズ別ではなくまとめて糸量を管理できる
- **糸量（現在庫）**: 今その号機にある量を登録する。不良で多く使った、他の品番へ回した、といった増減はここを直す。「残り必要量を入れる」ボタンで理論値を初期値として入れられる
- **編める反数の自動計算**: 「現在庫 ÷ 1反あたりの消費量」で**今ある糸であと何反編めるか**を算出し、残り反数と比較して不足反数を表示。ロスで理論どおりに減らないため、在庫を直すたびに再計算される
- **次の品番**: 進行中のオーダーとは別に、次の品番の反数・重量・開始日・完了予定日・番手・交編率・糸量を登録できる。糸を先に手配するための必要量も算出
- **生産の開始**: 「この品番を開始する」で次のオーダーを現在のオーダーへ引き上げる。開始日は今日、状態は「稼働中」になり、開始時にアニメーションが流れる
- **途中切り替え**: 残反がある状態でも切り替えられる。その場合は確認画面と案内文に残反数が出て、履歴に「中断」として実績（何反/何反）が残る
- **履歴**: 切り替えで終了・中断したオーダーを編集画面で確認できる（品番・期間・実績反数・中断の有無）。7件以上ある場合は「すべて表示」で全件に切り替えられる
- **完了予測**: 水揚げを記録した日数から日平均の反数を求め、残りを消化しきる日を予測。予定日と比べた遅れ・前倒しも表示
- **水揚げ記録**: 毎朝の水揚げを反数で記録すると累計・残り生産量が更新され、原糸必要量が自動で再計算される。シークバーは1反刻みで動き、kg換算値も併記。記録の取り消しにも対応

## 計算式

```
合計生産量 = 重量(1反あたりのkg) × 反数
原糸必要量 = 生産量(kg) × 交編率(%) × (1 + ロス率(%))
日平均の反数 = 水揚げ履歴の合計反数 ÷ 記録した日数
完了予測日   = 今日 + ceil(残り反数 ÷ 日平均の反数)
1反あたりの糸 = 重量 × 交編率(%) × (1 + ロス率(%))
編める反数    = floor( min( 現在庫 ÷ 1反あたりの糸 ) )
使った量      = 最初に買った量 − 現在の糸量
実ロス率      = 使った量 ÷ (水揚げ済みの生産量 × 交編率) − 1
```

数量は kg・% とも**小数第2位**まで入力・表示できます。反数は整数です。

完了予測の母数は「水揚げを記録した日数」です。動かさなかった日は含めないため、稼働日ベースのペースになります。

- **全体必要量**: 合計生産量を基準にした、オーダー全体で必要な糸量
- **残り必要量**: 編残（合計生産量 − 水揚げ累計）を基準にした、これから必要な糸量
- **過不足**: 現在庫 − 残り必要量（マイナスは不足）
- **編める反数**: 今ある糸で編める反数。残り反数を下回っていればその差が不足反数
- **実ロス率**: 買った量から実際に減った量を、計算上の正味消費量と比べた比率。設定のロス率より大きければ、不良や糸切れで想定以上に使っていることになる

ロス率の既定値は **3%**（＝×1.03）で、機械ごとに変更できます。

**計算例**（合計生産量1000kg／交編率 表50%・中20%・裏30%／ロス率3%／水揚げ累計400kg）

| 糸 | 全体必要 | 残り必要 |
|---|---|---|
| 表糸 | 515.00 kg | 309.00 kg |
| 中糸 | 206.00 kg | 123.60 kg |
| 裏糸 | 309.00 kg | 185.40 kg |

## データについて

- データは**端末のブラウザ内（localStorage）**に保存されます。アプリを閉じても消えませんが、端末・ブラウザをまたいだ共有はされません。
- 保存キー: `factory-machines-v1`（表示形式は `factory-list-mode`、最終バックアップ日時は `factory-last-backup`）
- **端末を替えるときや、ブラウザの保存データを消す前には必ず書き出してください。** ホームの「データの保管」から行えます。
- 複数端末での共有や既存の Notion／GAS 基盤との連携が必要になった場合は、保存処理（`loadMachines` / `saveMachines`）を差し替えることで対応できます。

## データモデル

| フィールド | 型 | 説明 |
|---|---|---|
| `id` | string | 一意のID（自動生成） |
| `no` | string | 号機番号（例: "01"） |
| `model` | string | 機種名 |
| `status` | enum | `running`（稼働中）/ `changeover`（段取り中）/ `stopped`（停止）/ `idle`（計画停止） |
| `sku` | string | 現在の品番 |
| `group` | string | 案件名（空文字なら単独。同じ名前の号機どうしが1つの案件） |
| `uptime` | number | 稼働率（0〜100の整数、%） |
| `startDate` | string | 開始日（YYYY-MM-DD） |
| `nextChange` | string | 次回予定日（YYYY-MM-DD） |
| `note` | string | メモ |
| `rolls` | number | 反数 |
| `weightPerRoll` | number | 1反あたりの重量(kg) |
| `totalKg` | number | 合計生産量(kg)。`weightPerRoll × rolls` で自動算出 |
| `producedRolls` | number | 水揚げ累計(反) |
| `producedKg` | number | 水揚げ累計(kg)。`producedRolls × weightPerRoll` で自動算出 |
| `lossPct` | number | ロス率(%)（既定3） |
| `ratio` | object | 交編率 `{ f: 表, m: 中, b: 裏 }`（%） |
| `onHand` | object | 現在の糸量（在庫）`{ f: 表, m: 中, b: 裏 }`（kg） |
| `purchased` | object | 最初に買った糸量 `{ f: 表, m: 中, b: 裏 }`（kg） |
| `counts` | object | 番手 `{ f: 表, m: 中, b: 裏 }`（文字列） |
| `log` | array | 水揚げ履歴 `[{ d: "YYYY-MM-DD", rolls: number }]` |
| `next` | object | 次のオーダー（`sku` / `rolls` / `weightPerRoll` / `totalKg` / `startDate` / `endDate` / `lossPct` / `ratio` / `counts` / `onHand` / `purchased`） |
| `history` | array | 完了・未達・中断したオーダーの控え（`sku` / `rolls` / `producedRolls` / `remainRolls` / `completed` / `short` / `partial` / `startDate` / `closedAt` / `counts` / `purchased` / `leftover` / `log`） |

古い形式で保存されたデータは読み込み時に自動で新形式へ変換されます。重量を持たない旧データは合計生産量と反数から重量を逆算し、kg基準の水揚げ履歴は反数へ換算して移行します。

## 起動画面

アプリを開くと、回転するワイヤーフレーム球体と進捗表示のアニメーション（約2.3秒）が流れてから本編に入ります。画面をタップすればすぐスキップできます。

不要になった場合は `index.html` の `<div class="boot" id="boot">` のブロックと、末尾の起動画面用スクリプトを削除してください。表示時間は同スクリプト内の `DURATION` で調整できます。`prefers-reduced-motion` を有効にしている端末では自動的に短縮されます。

## デザイン

モバイルゲーム「アークナイツ」のUIを参考にした構成。ぼかした施設内観風の背景（`bg.jpg`）の上に明るい半透明パネルが浮かぶレイアウト、彩度を抑えた配色に青（`#29a1e0`）のアクセント、小さな英字ラベル（`sku` `uptime▶` `output▶`）の併記、左に見出しブロックを置く行レイアウトを採用しています。状態は塗りタグ、糸は系統色（表=青／中=橙／裏=緑）で識別します。

号機一覧のタイル表示は同ゲームの基地画面を模しており、暗いタイルを敷き詰め、左端の色帯で状態、名前の右のピップで稼働率、右下の大きな数字で反数を示します。

背景画像はCSSの図形とぼかしから生成したオリジナル画像で、外部素材や外部CDNには依存していません（約26KB）。

`bg.jpg` を差し替えた際は、`index.html` の `url("bg.jpg?v=N")` の番号を上げてください。ブラウザが古い画像をキャッシュしたままになるのを防ぐためです。

## 更新が反映されないとき

ホーム画面に追加したアプリは、iOSが以前読み込んだ画面を持ち続けることがあります。更新したのに変わらない場合：

1. **Safari**（ホーム画面のアイコンではなく）で `https://5gr2pb25dj-jpg.github.io/N/?r=1` のように末尾に `?r=1` を付けて開く。数字を変えれば毎回新しく取得されます
2. 起動画面の右下、またはホームの「データの保管」に出る `Ver` の日付で、いま動いている版を確認できます
3. ホーム画面のアイコンから開いた場合は、画面を下に引っ張って更新（プルダウン）

**「設定 → Safari → 履歴とWebサイトデータを消去」はしないでください。** 登録した号機のデータも一緒に消えます。

`sw.js`（Service Worker）を入れてあるため、一度新しい版を読み込めば、それ以降は起動のたびにネットワークから最新の画面を取りに行きます。圏外のときは直前に取得したもので動きます。

### 更新を出すときの手順

`index.html` の `APP_VERSION` と `sw.js` の `VERSION` を**両方**同じ値に上げてください。値が変わるとキャッシュが作り直されます。
